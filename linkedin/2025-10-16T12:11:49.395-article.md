🔄 Sometimes you are faced with circular dependencies between tables in the database. Here are two techniques how to resolve the problem and a few notes on what to be aware of.


👉 Circular dependencies can arise when you want to model tree or graph like structures or hierarchies and have a table of nodes (messages in this example) and whole branches or groups of those nodes (conversations).

You can encounter circular dependencies also in places where one table complements another, such as in double entry book keeping and the debit and credit tables.


🤔 The first approach is to eliminate the circular dependency and instead introduce a “join” table like conversation_leafs, where you would map conversation_ids to the message_id that is the last one in a conversation – a leaf in the conversation tree.

Any time you want to have the conversation information including the last message_id, you have to do a join on those two tables. The alternative being to sort the messages by timestamp and take the most recent one which could be expensive or limiting in a different way.


🤨 The lesser known approach is to change when the foreign key constraint is being enforced. Normally PostgreSQL evaluates constraints immediately but we can change this to evaluation at the end of a transaction with DEFERRABLE, basically stopping constraints from disturbing our circles until we have made everything whole again.


☝️ By deferring constraint enforcement you can also introduce performance degradation when the DB cannot rely on the fact that something will always be unique preventing optimizations such as join elimination. This shouldn't be the case in our example though because we are not deferring the uniqueness check but it's something to be aware of. Always EXPLAIN ANALYZE when in doubt.

CREATE TABLE IF NOT EXISTS conversations (
  conversation_id uuid PRIMARY KEY,
  title VARCHAR,
  leaf_message_id uuid UNIQUE NOT NULL,
  ...
);

CREATE TABLE IF NOT EXISTS messages (
  message_id uuid PRIMARY KEY,
  previous_message_id uuid REFERENCES messages(message_id),
  content VARCHAR,
  conversation_id uuid REFERENCES conversations(conversation_id) ON DELETE SET NULL,
  ...
);

ALTER TABLE conversations
  ADD CONSTRAINT fk_conversations_leaf_message
  FOREIGN KEY (leaf_message_id)
  REFERENCES messages(message_id)
  DEFERRABLE INITIALLY DEFERRED;

-- New conversation with a message
BEGIN;

INSERT INTO conversations ...;

INSERT INTO messages ...;

  SET leaf_message_id = new_message_id
  WHERE message_id = new_message_id;
