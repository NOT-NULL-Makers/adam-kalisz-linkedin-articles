How hard is it to implement a simple persistent e-mail queue in #Clojure and #PostgreSQL?


The bare minimum is to enqueue an e-mail into a suitable database table, get it from the table using the well known FOR UPDATE SKIP LOCKED query pattern and to update the status of the email, to delete it from the queue or mark it for deletion as needed. In this case, we use the HoneySQL Domain Specific Language to fit better in our Clojure code base instead of direct SQL.


The other part that is usually not mentioned is the polling of the #queue or some kind of triggering an event that e.g. an e-mail has been added to the queue. The second usually involves LISTEN/ NOTIFY but we have decided to just poll in regular intervals and process a batch of e-mails. That's good enough for now but we might add some kind of token bucket implementing an e-mail queue that's more dynamic and allows for bursts of activity while controlling the short and long term average rate limit.
