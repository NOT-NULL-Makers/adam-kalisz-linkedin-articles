Time flies and I have two Prague PostgreSQL Meetup to report about, one in that took place in April and the other on June 1st.


In the April edition with Artjoms Iškovs and Andreas Scherbaum the focus was on big scale and the evolution in the ecosystem.


Artjoms of EDB spoke about what people use for analytics and tools/ systems you can use besides #PostgreSQL, which is still more focused on transaction processing than large analytics jobs. After delving into the background and history of the various formats and approaches he also spoke about the Postgres Analytics Accelerator (PGAA) extension that allow Postgres to run queries on lakehouse formats such as Iceberg or Delta Lake which can even be stored in object storage.


Andreas spoke about the reopening of the Greenplum codebase in WarehousePG that was closed after Broadcom bought VMware. WarehousePG is interesting because it allows you to treat multiple PostgreSQL instances as one big server. This is again an approach to large scale analytics and high availability. Not suitable for OLTP workloads as for each query you have at least 3 network round-trips because of the coordinator. Also, the PostgreSQL compability is little behind, the currently mostly compatible release is PostgreSQL 12. The great thing is this is a clear path forward for those stranded on Greenplum version 6 or 7.


Yesterday Laurenz Albe of CYBERTEC PostgreSQL Services and Support spoke about some security attacks on PostgreSQL to be aware of. I decided to record the presentation on my phone spontaneously and to put it on YouTube: https://www.youtube.com/watch?v=CiDimWJkeNw for its importance in the current industry landscape.


Ants Aasma spoke about how to uncover the parts of queries that make them slow besides looking at EXPLAIN output really carefully. One hint is if the row count estimate in the plan does not closely match the actual execution row count. If things get thrown away, maybe we shouldn't spend much time calculating them in the first place. Ants also spoke about how to force the planner to do certain things and get more useful information. In general he advised to look for the 10x speedups, not the 10% adjustments.


Josef Šimánek spoke about what it takes to run on your own hardware at a certain scale. He showed in a demo how you can use system tools such as strace/ ltrace to find out what's the problem once you already started a query. Pavel Stěhule suggested to use Linux perf for that. All of this assumes rather low level access to the database instance.


Thanks Gülçin Yıldırım Jelínek and Mayuresh B. for organizing and Dataddo for hosting both meetups in your Holešovice office.

Bringing Postgres to the data lake: Iceberg, Delta Lake, and how we made Postgres read to and write from them - Artjoms Iškovs
Our Postgres Analytics Accelerator (PGAA) is an extension for Postgres that allows it to run queries on lakehouse formats (Iceberg, Delta) in object storage using a separate query engine (Apache DataFusion or Apache Spark). When coupled with Postgres Distributed, it can also replicate tables and changes to them to these formats.
This talk will do a deep dive on the Iceberg format, including its lesser-known features like equality deletes, position deletes and deletion vectors, as well as discuss how we integrate with Postgres Distributed's replication to turn Postgres into a hybrid transactional-analytical (HTAP) database.

How we made WarehousePG Open Source (again): What happened to Greenplum Database? - Andreas Scherbaum
WarehousePG is an Open Source fork of Greenplum Database, which by itself is a fork of PostgreSQL. The project was born after the upstream project was made closed source.
This talk gives a quick overview of the history of both projects, which already spans more than two decades. We then dive into the reasons for creating a fork, and all the stumbling stones we had to pass in order to make this project open source again. We also talk about the challenges of CLAs (Contributor License Agreements) and what implications the PostgreSQL and Apache Licenses have for the project.
